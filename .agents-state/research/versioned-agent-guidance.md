# Version-matched guidance for NeoHaskell coding agents

Research date is 2026-10-22. The audience is coding agents building NeoHaskell applications. Runtime agents inside those applications are outside scope. This report supplies facts for the pending authority and update decision. It does not choose that policy.

## Findings that affect the decision

The framework source revision and the installed guidance currently have separate provenance. `neo new` replaces its default `main` with the embedded starter's NeoHaskell lock revision. `neo skills setup` fetches the separate skills repository's default HEAD. Its command path does not read `neo.json` or resolve the application's framework version. This is a source-code finding, not a runtime experiment. See [new.rs lines 309-321](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/commands/new.rs#L309-L321), [skills command lines 36-63](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/commands/skills.rs#L36-L63), and [skills fetch lines 386-433](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/network.rs#L386-L433).

A published index is different from an agent's startup instructions. The llms.txt proposal describes web discovery and retrieval. Codex and Claude document local instruction loading separately. No source reviewed establishes that every coding agent automatically requests a framework website's llms.txt merely because the dependency is installed. This is a limit of the evidence, not a claim that no agent ever fetches it. Sources are linked below.

Turborepo now documents a similar bundled-doc pattern. Agent detection can maintain a uniquely marked repository `AGENTS.md` block. Its instructions resolve the installed `turbo` package and read `docs/README.md` before other bundled pages. The docs match the installed version and work offline. Existing instructions and other managed blocks survive updates. Its guide says to opt in with `agentGuidance: true`; the default starter already includes guidance. This establishes another first-party implementation pattern, not NeoHaskell's chosen design. [Turborepo guide](https://turborepo.dev/docs/guides/ai#version-matched-agent-guidance).

Context7 freshness is asynchronous. A request can trigger a refresh after a popularity-dependent threshold, while that request receives existing indexed documentation. Current thresholds range from one day to 45 days. Git sources refresh from the configured branch. Thus "up-to-date" does not establish synchronous publication or exact commit correspondence. [Keeping libraries fresh](https://context7.com/docs/library-updates). Its owner configuration supports `previousVersions` tags and `branchVersions` branches. [Library owner configuration](https://context7.com/docs/library-owners).

## Native instruction discovery has agent-specific rules

Codex builds its instruction chain at startup. It checks `AGENTS.override.md`, then `AGENTS.md`, then configured fallback names in each applicable directory. It combines project files from the repository root to the working directory. The default combined limit is 32 KiB. Therefore a short local pointer can enter startup context, but a whole documentation tree does not automatically enter it. [Official Codex instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance).

Claude Code reads `CLAUDE.md` at session startup. Current documentation says direct `AGENTS.md` support requires v2.1.277+. By default, an ancestor `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` makes Claude read those files instead of `AGENTS.md`. An explicit `@AGENTS.md` import or the relevant project-instructions setting changes that behavior. Earlier versions and some sessions need the import. This caveat limits the broader discovery language in framework documentation. [Official Claude memory documentation](https://code.claude.com/docs/en/memory#agentsmd).

These are documented product contracts checked on the research date. No live Codex, Claude, Cursor, or Kiro session was launched to measure actual loading or task success. No cross-agent guarantee or measured improvement is claimed.

## Current NeoHaskell paths and compatibility identity

1. `neo new` embeds `neo/starter/` through `RustEmbed`. The revision for a new application's default `neo-version` comes from embedded `flake.lock`, `nodes.neohaskell.locked.rev`. It is validated as a full 40-hex SHA. The CLI binary version and its own source commit are not automatically the application's framework commit. [network.rs lines 263-288](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/network.rs#L263-L288).
2. Reconciliation keeps both the requested `neo_version` and resolved `neo_sha`. A full SHA passes through unchanged. Other refs resolve through `git ls-remote`; `main` and `latest` select `main`. Consequently a branch name is not an immutable compatibility identity. `NEO_SKIP_NETWORK` returns test placeholders and does not prove real offline dependency resolution. [resolve.rs lines 24-37 and 83-100](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/reconcile/resolve.rs#L24-L100), [network.rs lines 18-79](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/network.rs#L18-L79).
3. Generated Cabal sources use the resolved framework commit. The consumer-verification `NEO_NEOHASKELL_SOURCE` override instead selects a local checkout's HEAD for both Nix and Cabal. A future compatibility reader must account for that explicit override if its scope includes consumer tests. [cabal_project.rs lines 32-38](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/reconcile/cabal_project.rs#L32-L38), [template lines 9-21](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/assets/templates/cabal.project.j2#L9-L21), [local override lines 38-89](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/reconcile/flake.rs#L38-L89).
4. `neo skills setup` installs Claude, Codex, Kiro, and Cursor adapters. Claude gets a primer import. Codex and Kiro get inline primer blocks in `AGENTS.md`. Cursor gets an always-apply rule. These are the CLI's configured targets, not independent proof of every target's current native behavior. The cache follows skills-repository HEAD when reachable. An existing cache survives an unreachable upstream unless `--refresh` forces cloning. [tool table lines 97-105](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/skills.rs#L97-L105), [fetch lines 386-433](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/network.rs#L386-L433).
5. Skill-folder replacement removes the destination before copying. Changed destinations require interactive confirmation or `--force`; CI fails without it. Managed primer updates preserve content outside markers, leave malformed markers untouched, and warn about duplicate blocks. Edits inside the managed region are replaced. A modified primer file can be skipped while its managed wiring still updates, so "preserves user edits" needs a precise ownership boundary. [overwrite policy lines 120-155](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/commands/skills.rs#L120-L155), [replacement lines 526-546](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/skills.rs#L526-L546), [managed updates lines 608-673](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/src/skills.rs#L608-L673).

The starter README claims an `AGENTS.md` and `.skills/` onramp, but neither exists in the tracked embedded starter at this baseline. `neo new` has no skills-setup invocation. This is an inventory finding. Reproduce with `git ls-tree -r --name-only cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca neo/starter` and `git grep -n -E 'skills|primer|AGENTS|CLAUDE' cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca -- neo/src/commands/new.rs`. The second command returns no matches. [README claims at lines 12 and 199](https://github.com/neohaskell/NeoHaskell/blob/cbdc45f1bb89c9c7bb8da9fbdb25343771d924ca/neo/starter/README.md#L12).

## Remaining human decisions and verification limits

The research supports the resolved source SHA as an available exact compatibility key. Choosing its authority, guidance publication, historical corrections, update trigger, adapter support, and edit ownership remains the pending decision ticket's work. Context7's documentation did not prove arbitrary-SHA coverage, and no external service was configured to test that claim. No feature implementation, generated-app runtime test, or agent-behavior evaluation was performed.

The Prove It Works principle changed verification here. The report uses source permalinks and reproducible inventory commands, and completion requires reading back the pushed artifact and actual Plane state. Documentation claims and inferred design possibilities remain separate.
