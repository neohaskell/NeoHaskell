# Installer entrypoints before removal

**Question.** Which current first-party installation entrypoints depend on the monorepo installer bootstrap or `installer-v*` assets, and what coordination is needed before deleting the component?

**Finding.** `installer/README.md` in the public NeoHaskell monorepo is the one maintained first-party entrypoint found that depends on the installer. It publishes a curl command for the mutable raw `main/installer/scripts/bootstrap.sh` URL and documents manual `neo-install-*` downloads. The bootstrap resolves an `installer-v*` release asset. Removing the component from `main` therefore retires this command and the installer's README instructions. [README at public main `7bd77c0`](https://github.com/neohaskell/NeoHaskell/blob/7bd77c0fd88a4b56091fc015388df85837e97d96/installer/README.md) · [bootstrap at the same commit](https://github.com/neohaskell/NeoHaskell/blob/7bd77c0fd88a4b56091fc015388df85837e97d96/installer/scripts/bootstrap.sh)

The maintained website source points users directly to native `neo-*` release assets, then uses `neo new` and `neo build`; a targeted search of that repository found no bootstrap URL, `installer-v*` tag, or `neo-install-*` reference. The source snapshot is website-v2 commit `34fe7b72d1c2a20f8fcfdf307e5bb5ee33942e29`. This establishes what the maintained docs source says, not what is deployed. [Website getting-started source](https://github.com/neohaskell/website-v2/blob/34fe7b72d1c2a20f8fcfdf307e5bb5ee33942e29/src/content/docs/getting-started/index.mdx) · [Website repository description](https://github.com/neohaskell/website-v2/blob/34fe7b72d1c2a20f8fcfdf307e5bb5ee33942e29/README.md)

On 2026-10-21, `https://neohaskell.org/` returned 200 and its root page exposed no installation or documentation link. The checked routes `/getting-started/`, `/docs/`, and `/getting-started/installation` returned 404. The live deployment therefore does not provide a verified current docs entrypoint to migrate. These checks do not establish the deployment state of every route or cached page. [Live site](https://neohaskell.org/) · [checked getting-started route](https://neohaskell.org/getting-started/) · [checked docs route](https://neohaskell.org/docs/) · [checked historical installation route](https://neohaskell.org/getting-started/installation)

**Compatibility boundary.** The raw bootstrap URL is a public source URL, so copied scripts may call it; available first-party evidence cannot identify or rule out those external consumers. The published `installer-v0.1.4` release still has four installer binaries, each with a small nonzero GitHub download count (3–6 at inspection). Counts do not identify people, current use, or automated consumers. Deleting source and CI does not itself delete those historical tags or assets. [Installer release](https://github.com/neohaskell/NeoHaskell/releases/tag/installer-v0.1.4) · [GitHub release metadata](https://api.github.com/repos/neohaskell/NeoHaskell/releases/tags/installer-v0.1.4)

A first-party DEV article dated 2025-03-27 also published `https://sh.neohaskell.org | bash`; that URL returned 404 when checked. It is historical evidence, not a current working entrypoint. [Original announcement](https://dev.to/neohaskell/introducing-neo-a-cli-tool-for-your-neohaskell-projects-58gp)

**Coordination needed.** No separate first-party website-source migration is indicated before removal. The removal change should retire `installer/README.md` and its command with the component. This is a public compatibility break for the raw `main` bootstrap URL; no available source can establish whether external scripts still use it. Keep that limitation visible in the change announcement. Direct Neo CLI installation and generated-project verification remain independent of this installer path. [Current direct Neo release](https://github.com/neohaskell/NeoHaskell/releases/tag/neo-v0.10.1)

**Draft research resolution.** Inspected current public monorepo source, maintained website-v2 docs source, checked live site routes, and public release metadata. The only maintained first-party entrypoint found that depends on the installer is `installer/README.md` and its raw `main/installer/scripts/bootstrap.sh` command; website-v2 installs direct `neo-*` assets. The raw bootstrap URL is a public compatibility break, but external script usage cannot be determined from available evidence. No separate first-party website migration was found.

**Scope.** This is a source and public-metadata check, not a survey of external consumers. The installer was not downloaded or run. No external migration or release-asset deletion was performed.
