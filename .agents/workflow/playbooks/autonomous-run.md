### Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.**

1. State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero). For NeoHaskell, match it to the affected compiler consumer, demanded pure result, executed Task/decision or actual service outcome; command acceptance alone does not prove downstream completion.
2. Pick the wake mechanism through the available roles and execution/wait facilities in `AGENTS.md`. An event to watch (CI, a merge, a ref advancing) gets a watcher subagent that wakes you on the event, with a long time-based heartbeat as fallback. No event gets a fixed-interval heartbeat sized to when the result is worth re-checking. Keep one supervisor and respect delegation capacity. Report unavailable persistence rather than promising monitoring beyond the session.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, discards changes that didn't help. Belt-and-suspenders that "might help" gets reverted, not left to ride.
   Sequence the work via the **sequence-verifiable-units** principle skill, verifying each coherent type/instance/generator/consumer unit before the next instead of batching checks at the end; follow declared migration phases when temporary breakage is planned.
4. Mid-run discoveries are yours. Address broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift yourself following `AGENTS.md`, within the task's existing scope and authorization. Do not park authorized reversible work for the human. Surface only actions needing new authorization, genuine product or preference calls no experiment can settle, or a real dead end. Keep the predicate as the main drive, and return to it after each side fix.
5. Checkpoint every iteration via the **show-me-your-work** skill, a row for what changed and whether the predicate moved. Keep reproduction inputs, logs and decision evidence under repository-root `.agents-state/`.
6. Stop when the predicate is met, and honor an explicit stop or hold. Derive the delivery boundary from the [task completion policy](../../skills/orchestrate/references/task-completion.md), then follow Shipping when landing is in scope. A completion predicate cannot override an explicit no-merge limit. A plateau is not a stop, so keep going and pivot your approach to push past it. Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory.

**Reply:** the exit condition, iterations run, what landed, what was discarded, final predicate state.
