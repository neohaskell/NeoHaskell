# Service-code rule enforcement

This matrix describes the checks introduced after [PR #934](https://github.com/neohaskell/NeoHaskell/pull/934). The inspected source base is `deacffb43babc44cc12855f0897d7259901b3c33`. Guidance governs design choices. HLint covers parsed syntax. Existing compiler checks and focused runtime tests must prove semantic guarantees in the production follow-up.

| Rule and owner | Inspected source example | Enforcement and limit |
| --- | --- | --- |
| [Names for a junior TypeScript reader](../../principle-name-for-the-reader/SKILL.md) | [AsyncTask.runUnmasked](../../../../core/concurrency/AsyncTask.hs) | Review the observable cancellation contract before naming. No word blacklist can prove comprehension. The production rename is deferred. |
| [Shallow orchestration and coherent configuration](../../neohaskell-best-practices/references/readable-services.md) | [CommandExecutor.Core.execute and executeInner](../../../../core/service/Service/CommandExecutor/Core.hs) | Review named responsibilities, roughly three or four ordinary arguments, stable configuration, and changing data last. Argument or indentation counts alone cannot distinguish a good boundary. |
| [Task error composition](../../neohaskell-best-practices/references/readable-services.md) | [Task.recover and mapError](../../../../core/core/Task.hs) | HLint rejects recovery that only throws a translated error. Positive and negative fixtures exercise the actual hint. Cases that inspect Result values still require semantic review. |
| [Core exception ownership](../../neohaskell-best-practices/references/readable-services.md) | [CommandResultReceipt.Internal.reportIfRegistered](../../../../core/service/Service/CommandResultReceipt/Internal.hs) | HLint restricts exception imports and named calls to Task and AsyncTask. Alias and unqualified-use fixtures prove import resolution. Existing exact debt remains. Task-to-IO-to-Task cycles require review because IO adapters can be legitimate. |
| [Core mutable state and thread inspection](../../neohaskell-best-practices/references/readable-services.md) | [CommandExecutor.Core local references](../../../../core/service/Service/CommandExecutor/Core.hs), [DispatcherSpec threadStatus](../../../../core/test/Integration/DispatcherSpec.hs) | HLint restricts IORef imports and operations to Var, and named thread operations to AsyncTask. Atomicity belongs to the owning API and runtime tests. No automatic Var substitution is proposed. |
| [Closed outcomes and valid construction](../../principle-type-system-discipline/SKILL.md) | [IntegrationRunnerOutcome and failure text helpers](../../../../core/service/Service/Integration/Dispatcher.hs) | Compiler constructor coverage and owning constructors or decoders provide the guarantee. Review distinguishes external diagnostics from internal labels. No blanket ban on Text or manual JSON is sound. |
| [Typed serialization](../../neohaskell-best-practices/references/readable-services.md) | [Dispatcher writeIntegrationResult and failure fields](../../../../core/service/Service/Integration/Dispatcher.hs) | Prefer derivation. | [Focused type modules and proportional SOLID](../../principle-minimize-reader-load/SKILL.md) | [Dispatcher outcome, queue, and worker operations](../../../../core/service/Service/Integration/Dispatcher.hs) | Review whether moving a type and its operations reduces tracing. Proposed IntegrationOutcome.text is explicitly not an existing API. No mandatory module size or interface count. |
| [Useful module headers](../../no-comments/references/comment-reviewer.md) | [AsyncTask module and public operations](../../../../core/concurrency/AsyncTask.hs) | The comment reviewer now permits short responsibility and usage headers. Phase narration and workaround histories remain outside the exception. |
| [Scoped temporary test resources](../../neohaskell-best-practices/references/readable-services.md) | [StorageMetadataSpec basePath](../../../../core/test/Service/CommandExecutor/StorageMetadataSpec.hs) | The source scanner rejects new literal agent-workspace references, including Python helpers. One exact existing occurrence remains. The core Directory API is missing and must precede its removal. |
| [No new migration debt](static-checks.md) | [Exact inventory](lint-debt.json) | The gate rejects new identities, increased counts, stale entries, and parse failures. Pruning cannot accept new debt. Inline ownership suppressions do not hide findings. The documented lexical and CPP limits still apply. |

The fixtures prove lint acceptance and rejection. They do not compile the illustrative modules or establish runtime cancellation, storage, or serialization behavior.
