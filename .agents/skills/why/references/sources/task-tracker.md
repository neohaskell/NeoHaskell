# Task tracker evidence

Discover the project's task tracker and scope from its instructions, linked tasks, or configured evidence sources. Use an available connector, CLI, or API read interface; follow an explicitly supplied task link directly. Read only; do not create tasks, add comments, assign work, or change state during an investigation.

1. Start with tasks linked by the code anchor, commits, or pull requests. Read descriptions and relevant comments, including explicit resolutions and later amendments.
2. Search the relevant project or workspace by feature names, Haskell symbols, service names, error text, and design terms. Record the queries and scope.
3. Follow parent, duplicate, related-task, and dependency relationships when they bear on the rationale. Hand external document or PR links to the corresponding investigator.
4. Distinguish a proposed approach from a settled decision. A closed state by itself does not establish which rationale or implementation was accepted; check the recorded resolution and later corrections.
5. Return the task title and URL or identifier, relevant author/date, precise quotations or paraphrases, and the source of each claimed decision. Name inaccessible tasks or missing comments as gaps.
