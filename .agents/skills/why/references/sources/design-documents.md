# Design document evidence

Discover the project's relevant design documents from its instructions, links in the code anchor, and available evidence sources. Search through the available local or remote read interfaces. Let the project determine document locations and systems.

1. Find documents addressing the target symbols, service contracts, tradeoffs, or language feature. Use linked documents and focused text searches before expanding the search.
2. Read the relevant document, its status, rationale, alternatives and amendments. Check proposal status where applicable and cite the revision or date inspected. A draft describes a proposal; acceptance records a design decision but does not by itself prove implementation.
3. When the question concerns audience or design priorities, consult the applicable audience definitions and design principles. Treat those as context; attribute a particular code decision to them only when evidence connects that decision to the principle.
4. Compare the documented decision with the maintained code anchor and return mismatches explicitly. Hand source-control or task-tracker leads to the corresponding investigator.
5. Return document title, path or URL, status, author/date or revision when available, the pertinent section and evidence, and concrete gaps. Read only; do not amend documents or proposals during the investigation.
