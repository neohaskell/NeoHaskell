# Performance design review: Make cold-start health constant-time without losing replayed events
Spec: docs/changes/007-make-cold-start-health-constant-time.md | Capabilities: event-store, queries, entities | Date: 2026-09-01

| # | Checklist | Finding | Grounding | Verdict |
|---|-----------|---------|-----------|---------|
| 1 | P1 | Startup replay sits directly on event apply and persistence paths. The design removes the measured anti-patterns: synchronous pre-bind replay, one global-log pass per query, uncached entity reconstruction, and per-operation pool construction. | kept: production incident measured 82-320s startup gaps; paths are exercised for every historical event; framework absorbs the change; proportional | advisory |
| 2 | P3/P5 | Paging is only bounded if no page/catch-up path first materializes the unbounded log. The implementation must not use `Limit maxValue` with `Stream.toArray`; accumulation must remain bounded by `chunkSize`, and repeated `Array.push` must not grow an event-count-sized vector. | kept: current Postgres catch-up buffers the full log and `Array.push` is `Vector.snoc`; C2/C3 exercise the path; internal fix; proportional | advisory |
| 3 | P6 | Exactly-once ordering requires callback serialization because live dispatch enters concurrently. A single bounded positional inbox/monotonic cursor is appropriate during catch-up; after reaching head, the path must not retain a global replay lock or whole-history map. | kept: two callback threads are part of the verified root cause; contention and retained history would affect the live event path; framework-internal; proportional | advisory |
| 4 | P5 | Entity routing must be resolved before entity fetch. One global pass should select only matching entity updaters and use the existing cached fetcher, avoiding wrong-entity fetches and repeated full-stream reconstruction. | kept: current Q×N plus N×u multiplier is concrete and C6 measures call count; no user knob; proportional | advisory |
| 5 | P7 | The spec's “flat across 1k/10k/100k” claim has an acceptance criterion. Treat PR timing as a regression bound, not a nightly throughput benchmark; add measured replay throughput/memory budgets to the existing nightly harness only if stable fixtures exist. | kept: claim is measurable and C9 supplies evidence; nightly benchmark remains non-PR-blocking | advisory |
| 6 | P2/P4 | No new exported polymorphic hot-path function or serialization codec is promised, so no `INLINE`/`INLINABLE`/`UNPACK` or codec change is justified without profile evidence. | informational (failed Q2: these paths are not introduced by the contract) | informational |

**Blockers:** 0 — the approved criteria cover the named scaling failures. Implementation must preserve bounded paging and avoid moving the full-log buffer behind an async boundary.
